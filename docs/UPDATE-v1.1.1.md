# SysPulse v1.1.1 更新报告

发布日期：2026-10-08。此版本修正内存和 GPU 的告警依据，沿用 v1.1.0 的原生玻璃面板、设置与动画。

## 为什么调整

资源占用率与资源压力含义不同。内存占用较高时，系统仍可能有足够资源响应新的请求；GPU 接近满载也可能只是正在完成游戏、视频导出或渲染任务。此前三个百分比读数共用 80% / 92% 阈值，容易把正常工作显示成告警。

## 新的配色规则

| 指标 | 面板与普通菜单栏数字 |
| --- | --- |
| 内存压力正常 | 保持原文字色，不按占用率变色 |
| 内存压力警告 | 橙色 |
| 内存压力严重 | 红色 |
| 内存压力未知或读取失败 | 中性色，并明确显示“未知” |
| GPU | 始终保持正常文字色，百分比与紫色曲线表达负载 |
| CPU | 保留原来的 80% 橙色、92% 红色规则 |

炫彩菜单栏仍保持冷色渐变；该模式下可在面板查看内存告警。GPU 缺值继续区分等待数据与机型未提供计数器。

内存百分比及曲线仍表示占用率，不转换为压力百分比。内存详情、菜单栏悬停提示、辅助功能朗读和 `--dump` 增加可读的压力状态。

## 数据来源与容错

每轮内存采样使用 `sysctlbyname("kern.memorystatus_vm_pressure_level")` 读取当前系统状态。该选择器返回四字节的外部压力等级：`1` 正常、`2` 警告、`4` 严重，不能与 XNU 内部的 `0/1/2/3` 枚举混用。

实现检查调用是否成功、返回长度是否为四字节以及值是否已知。失败、异常长度或未知值均显示“未知”，不沿用旧告警，也不以 RAM 占用率或交换容量代替压力。

这个具体 sysctl 选择器没有 Apple 对公开稳定性的承诺，因此保留运行时容错。三态读取不重现活动监视器的压力曲线，也不保证两者采样时刻相同。参考 [Apple 对内存压力的说明](https://support.apple.com/zh-cn/guide/activity-monitor/actmntr1004/mac) 与 [macOS 14 时期 XNU 的转换实现](https://github.com/apple-oss-distributions/xnu/blob/xnu-10002.1.13/bsd/kern/kern_memorystatus_notify.c)。

## 验证范围

- **201 项生产断言**通过，相较 v1.1.0 新增 84 项。覆盖压力值映射、读取失败、异常长度、失败后恢复、快照传递及实际面板配色选择。
- 两种系统外观、三种菜单栏密度的真实渲染验证通过：99% 内存占用且压力正常保持中性色，40% 占用且压力严重仍告警；GPU 80% / 100% 不显示告警色；CPU 保留阈值；压力变化不改变菜单栏尺寸；炫彩保留冷色字面。
- 原有 **24 个控制器场景、40 项原生玻璃生命周期与帧断言**通过。
- **64 项受控打包检查**通过，包含安装回滚、版本标签一致性、发布说明与校验文件生成；不修改真实登录项。
- **10 种原生面板状态及设置交互**通过，包含内存详情和浅色 / 深色外观。
- `arm64` 与 `x86_64` 使用 Swift 5、macOS 14 目标和警告按错误处理完成发布参数编译。

压力警告和严重状态通过隔离的 sysctl 读取夹具验证，没有对本机制造真实内存压力。实际运行环境为 Apple M5 / macOS 27.2；Intel 与 macOS 14 / 15 尚无实机运行验收。此版本未重新测量总体性能，也未重复 v1.1.0 的独立动画验证。
